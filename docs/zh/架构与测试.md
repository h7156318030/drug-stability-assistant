# 架构、测试与已知局限

[English](../en/architecture_and_testing.md) | **中文**

## 一、代码结构

| 文件 | 职责 |
|------|------|
| `app.py` | Streamlit 入口：登录、会话、权限检查、各功能页面（约 2170 行，UI 与业务交织，是后续拆分的主要对象） |
| `src/models.py` | 枚举（条件、设计、分子类型、CQA）、`TimePoint` / `Measurement` / `Sample` / `StabilityStudy` 数据类、限度与取值校验 |
| `src/planner.py` | 取样时间点计划、括号法 / 矩阵法设计、方案模板、矩阵设计取样缩减 |
| `src/analysis.py` | 回归与有效期推算、模型选择（线性 / 指数 / 逻辑斯蒂）、Bootstrap、留一法、离群值（MAD）、光稳定性、可比性、生物制品评价、Arrhenius 外推 |
| `src/db.py` | 数据访问层：研究、样品、时间点、检测值的增删改查，JSON 整库备份与恢复 |
| `src/auth.py` | 用户表、口令哈希（bcrypt）、登录失败锁定、角色权限矩阵、审计日志与哈希链校验、电子签名记录 |
| `src/report.py` | Excel（openpyxl）与 PDF（reportlab）导出 |
| `src/teaching.py` | 教学指南文本与合规清单 |
| `src/fonts.py` | matplotlib 中文字体配置 |
| `src/importers.py` | 批量 CSV 导入（UTF-8 / GBK 读取，必需列校验，跳过行原因）；与界面解耦 |
| `src/ui_theme.py` | 界面主题：配色 token、CSS、侧边栏品牌区、登录页、Plotly 图表模板 |

## 二、数据模型

```
studies ─1:N─ samples ─1:N─ time_points ─1:N─ measurements
                                  ▲
                 measurements.tp_ref 精确指向 time_points.tp_id
users                 （用户、角色、口令哈希、锁定计数）
audit_log             （仅追加；字段：操作人、时间(UTC)、动作、对象、IP、会话、前后值、备注）
```

- `tp_ref` 精确指向时间点，避免同一月份、不同条件的数据误配。
- SQLite 占位符为 `?`，PostgreSQL 为 `%s`，由 `db._sql()` 统一转换。
- 数据库外键通过 `PRAGMA foreign_keys=ON` 启用；删除研究时显式删除子表记录。

## 三、认证与审计

- 口令以 bcrypt 哈希保存；不保存明文。
- 登录失败达到阈值后锁定一段时间（字段 `failed_attempts` / `locked_until`）。
- 角色权限矩阵定义在 `src/auth.py` 的 `ROLE_PERMISSIONS`。
- 审计日志仅追加。`verify_audit_integrity()` 按哈希链检查记录是否被改动。
- 恢复备份时保留 `audit_log` 与 `users`，并追加一条恢复记录。

## 四、配置

| 环境变量 | 说明 |
|----------|------|
| `STAB_ADMIN_PASSWORD` | 首次创建 `admin` 时的口令；未设置时生成一次性随机口令输出到控制台 |
| `STAB_DATA_DIR` | SQLite 数据库目录；测试脚本会设置为临时目录 |
| `DATABASE_URL` | PostgreSQL 连接串；设置后不再使用 SQLite |

## 五、测试

运行全部测试：

```bash
python tests/run_all.py                                  # 本地快速运行，输出汇总
python -X utf8 -m unittest discover -s tests -p "suite_*.py"  # 与 CI 相同的 unittest 方式
```

GitHub Actions（`.github/workflows/test.yml`）在 Windows 上以 Python 3.9 与 3.11 运行后者。

| 脚本 | 内容 | 断言数 |
|------|------|--------|
| `tests/test_core.py` | 核心分析函数单元测试 | 12 |
| `tests/test_storage.py` | 存储层端到端：保存、读取、模板、导出 | 12 |
| `tests/test_ui_logic.py` | 页面逻辑（无数据与有数据） | 15 |
| `tests/test_regression.py` | 全链路回归与示例数据 | 17 |
| `tests/test_security_selfcheck.py` | 安全与数据完整性：级联删除、备份恢复、认证、边界条件 | 19 |
| `tests/test_reauth.py` | 敏感操作的口令复核与错误计数 | 5 |
| `tests/test_seed.py` | 示例数据工具可在空库上运行 | 2 |
| `tests/test_admin_flow.py` | 管理员页面渲染；删除研究须重新输入口令的完整流程 | 9 |
| `tests/test_functional.py` | 功能完整测试：数值与独立实现对照、全部模板、存储与审计、备份恢复、导出、认证与锁定、角色、CSV 导入 | 38 |
| `tests/test_ui_workflows.py` | 界面工作流：登录、角色导航、研究→样品→录入、教学示例、用户管理、改口令、四个角色下全部页面渲染 | 28 |

每个测试脚本都会设置 `STAB_DATA_DIR` 为临时目录，**不会改动正式的 `stability.db`**。`STAB_ADMIN_PASSWORD` 在测试中使用固定测试值。

**局限**：测试是自带断言的脚本，不是 pytest 套件；统计模块缺少独立的数值基准（外部参考值）校验；PostgreSQL 路径尚未在测试中覆盖。

## 六、已知局限与改进计划

1. **测试体系**：已接入 CI；但测试仍为自带断言的脚本，尚未拆为独立用例。补充 Bootstrap 与留一法的数值基准仍待完成。
2. **Part 11 差距**：删除研究与恢复备份已要求重新输入口令并记录签名。改口令、导出、用户管理等关键操作尚未纳入电子签名；审计字段中的 IP 与会话在本地部署时可能为空。
3. **PostgreSQL**：支持已实现，但未经完整实测。
4. **代码结构**：`app.py` 过大，UI 与业务逻辑混合，建议拆分为页面模块。
5. **界面语言**：当前界面为中文；英文界面尚未提供（文档已双语）。
6. **旧版管理员口令**：由旧版本创建的数据库仍可能使用 `Admin@2026`。管理员登录后侧边栏会提示修改，但程序不会强制修改。
