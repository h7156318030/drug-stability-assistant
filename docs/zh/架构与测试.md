# 架构、测试与已知局限

[English](../en/architecture_and_testing.md) | **中文**

## 一、代码结构

```
app.py                  入口：初始化、登录、侧边栏、语言切换、页面分发（约 150 行）
src/
  ui_common.py          界面公共工具：研究加载、持久化、权限检查、教学示例、常量
  pages/*.py            17 个页面，每个模块提供 render(ctx)
  ui_theme.py           主题、CSS、侧边栏品牌区、登录页、Plotly 模板
  i18n.py               语言切换（线程局部，中文为源语言）
  i18n_en.py            英文译文（键为中文原文）
  models.py             枚举、数据类、限度与取值校验
  planner.py            取样时间点计划、括号法 / 矩阵法、方案模板
  analysis.py           回归、有效期推算、Q1E 批合并检验、Bootstrap、留一法、
                        离群值、光稳定性、可比性、生物制品评价、Arrhenius
  db.py                 数据访问（SQLite / PostgreSQL）、整库备份与恢复
  auth.py               用户、口令、锁定、角色、审计日志与哈希链、电子签名记录
  importers.py          批量 CSV 导入（UTF-8 / GBK，必需列校验，跳过行原因）
  report.py             Excel（openpyxl）与 PDF（reportlab）导出
  teaching.py           教学指南文本与合规清单
  fonts.py              matplotlib 中文字体
tools/                  示例数据、命令行备份
tests/                  测试脚本（见第六节）
docs/zh, docs/en        文档
```

页面分发：`app.py` 中的 `PAGE_RENDERERS` 把导航名映射到 `src/pages/` 中的 `render(ctx)`，`ctx` 包含 `user`、`role`、`name`、`uname`、`studies`。

## 二、数据模型

```
studies ─1:N─ samples ─1:N─ time_points ─1:N─ measurements
                                  ▲
                 measurements.tp_ref 精确指向 time_points.tp_id
users                 （用户、角色、口令哈希、锁定计数）
audit_log             （仅追加；字段：操作人、时间(UTC)、动作、对象、IP、会话、前后值、备注）
```

- `tp_ref` 精确指向时间点，避免同一月份、不同条件的数据误配。
- 占位符 `?`（SQLite）与 `%s`（PostgreSQL）由 `db._sql()` 统一转换。
- 写入使用可移植的 `INSERT … ON CONFLICT … DO UPDATE` 与 `DO NOTHING`，同时适用于两种数据库。
- SQLite 通过 `PRAGMA foreign_keys=ON` 启用外键；PostgreSQL 由外键约束直接生效。

## 三、认证、审计与电子签名

- 口令以 bcrypt 哈希保存；仅要求至少 8 位（复杂度、有效期见差距分析）。
- 连续 5 次登录失败锁定 30 分钟（`failed_attempts` / `locked_until`）。
- 角色权限矩阵：`ROLE_PERMISSIONS`（`src/auth.py`）。
- 审计日志仅追加，`verify_audit_integrity()` 按哈希链检测篡改。
- **电子签名**（`reauthenticate` + `e_signature`）：以下操作要求重新输入登录口令，并写入 `ESIGN` 审计记录：
  - 删除研究；
  - 生成整库备份（备份含口令哈希）；
  - 整库恢复；
  - 创建用户、禁用 / 启用用户。
  口令错误计入锁定策略。
- 恢复备份时保留 `audit_log` 与 `users`，并追加一条恢复记录。

## 四、统计方法要点

| 功能 | 方法 | 说明 |
|------|------|------|
| 有效期 | 回归直线的 95% 单侧置信限与限度的交点（ICH Q1E） | `shelf_life` |
| 批合并检验 | ANCOVA 逐级 F 检验：先斜率，再截距；显著性水平 0.25 | `q1e_poolability` |
| 合并外推 | 批合并可行时合并回归，否则取单批最小值 | `pooled_expiry_extrapolation` |
| 稳健性 | 留一法（逐批剔除）与 Bootstrap（固定随机种子可复现） | `leave_one_out_expiry`、`pooled_bootstrap_ci` |
| 离群值 | 修正 z 分数（MAD，阈值 3.5），只标记不自动剔除 | `mad_outlier_detection` |
| 光照 | ICH Q1B 两个阈值（总照度、近紫外能量） | `photostability_exposure_ok` |
| 活化能 | ln k 对 1/T 线性回归（仅作初筛提示） | `arrhenius_extrapolate` |

## 五、配置

| 环境变量 | 说明 |
|----------|------|
| `STAB_ADMIN_PASSWORD` | 首次创建 `admin` 时的口令；未设置时生成一次性随机口令输出到控制台 |
| `STAB_DATA_DIR` | SQLite 数据库目录；测试脚本会设置为临时目录 |
| `DATABASE_URL` | PostgreSQL 连接串；设置后不再使用 SQLite |
| `STAB_TEST_PG_URL` | 仅用于 `tests/test_postgres.py`：指向一次性测试数据库 |

## 六、测试

运行全部测试：

```bash
python tests/run_all.py                                       # 本地快速运行，输出汇总
python -X utf8 -m unittest discover -s tests -p "suite_*.py"  # 与 CI 相同的 unittest 方式
```

PostgreSQL 测试（需要一个一次性数据库，测试会先删除其中的业务表）：

```bash
STAB_TEST_PG_URL=postgresql://user:pass@127.0.0.1:5432/stability_test python tests/test_postgres.py
```

未设置 `STAB_TEST_PG_URL` 时该测试输出 SKIP 并退出 0。CI 未配置 PostgreSQL 服务。

## 七、已知局限

1. **测试**：多数测试仍是自带断言的脚本，尚未拆为独立的 pytest 用例；CI 不含 PostgreSQL 服务。
2. **法规符合性**：存在若干 P0 差距，包括中间条件触发、暗对照、修改原因、电子签名与记录内容绑定、口令复杂度与会话超时、OOS/OOT 调查、方案审批门，以及计算机化系统验证文件。详见 [法规符合性差距分析](法规符合性差距分析.md)。
3. **界面语言**：界面文字已可切换为英文（见第八节）。以下内容仍为中文：分析结论的叙述性文字（如“批间存在显著差异”“非线性提示”）、图表标题与坐标轴、Excel 与 PDF 报告、设计建议页的规划说明，以及研究、样品、检测项目等用户数据。
4. **统计判据**：生物制品显著变化（效价下降超过 10%）、外推规则（批数、覆盖比例、外推倍数）等判据尚未对照官方原文核实，见差距分析与法规依据文档。
5. **旧版管理员口令**：由旧版本创建的数据库仍可能使用 `Admin@2026`，程序不会强制修改，仅在侧边栏提示。

## 八、界面语言

- 语言由页面顶部或侧边栏的下拉框切换（中文 / English），设置保存在会话中。
- 文字经 `i18n.t()` 查找，缺译时回退为中文，因此新增界面文字不会导致页面报错。
- 新增界面文字时：在代码中使用 `t("中文")`，并在 `src/i18n_en.py` 中补充对应英文条目（键须与中文原文完全一致）。占位符（如 `{0}`）两种语言须一致，`tests/test_i18n.py` 会检查。
